PART 1: ABOUT THE PROJECT (0:00 - 0:40)
========================================================================================
(Visual: Full screen on JanStream SRE Mission Control dashboard)

"Namaste! This is JanStream — a resilient public ingestion and emergency triage engine 
built for the Bharat Builds Tour: First Commit.

Across India, public portals for municipal grievances, scholarships, and disaster helplines 
frequently crash during traffic surges. 

During heavy monsoons, thousands of citizens upload 5-to-10 megabyte evidence photos of 
flooded streets, snapped power cables, and waterlogged roads simultaneously. Monolithic 
servers buffer these gigabytes directly into server RAM, triggering Out-Of-Memory pod 
crashes and HTTP 504 Bad Gateway timeouts.

Worse, life-threatening civic hazards — like an 11kV live power cable sparking in school 
floodwater — sit in the exact same chronological FIFO queue as a flickering street light.

JanStream solves this with a 100% serverless, event-driven shock absorber built on AWS."

========================================================================================
PART 2: TECH STACK & ARCHITECTURE (0:40 - 1:25)
========================================================================================
(Visual: Point mouse to the 6 telemetry nodes across the top)

"Here is our cloud architecture running on AWS in us-east-1:

1. Direct-to-S3 Cryptographic Ingestion: When a citizen submits evidence, our backend Lambda 
issues a temporary cryptographic S3 Presigned URL. The heavy evidence photo streams directly 
from the browser into Amazon S3. The backend Lambda processes only 200 bytes of JSON headers — 
consuming 0 MB of server RAM for file transfers!

2. SQS Backpressure Buffer: Submissions are queued into Amazon SQS (janstream-ingest-queue). 
Even if 10,000 requests arrive in 10 seconds, SQS acts as a shock absorber so the API tier 
never drops a single packet.

3. Automated AI Triage via Bedrock: Our worker invokes Amazon Bedrock (Claude / Nova) to 
evaluate unstructured citizen reports, parse Indian vernacular keywords like 'bijli', 'taar', 
'sparking', score urgency from 1 to 10, and assign responsible civic departments.

4. DynamoDB State Persistence: Lifecycle state transitions from RECEIVED to ESCALATED_EMERGENCY 
are committed in single-digit milliseconds to our Amazon DynamoDB table."

PART 4: LEARNING AND GROWTH (2:20 - 3:00)
========================================================================================
(Visual: Show the CloudWatch Structured Log terminal at the bottom)

"Building JanStream taught us three crucial architectural lessons:

1. True Serverless Cost Optimization: A traditional Kubernetes EKS cluster with managed nodes 
and load balancers costs $250 to $350 a month idling 24/7. JanStream is 100% scale-to-zero. 
During normal days with no civic crises, our operational cost is literally $0.00.

2. Decoupled Resilience: Decoupling heavy file bytes directly to S3 and decoupling state with SQS 
eliminates 99% of web portal crash vectors.

3. Graceful AI Fallback: We built a deterministic heuristic circuit breaker so even if foundation 
models throttle during high-latency events, zero citizen packets are ever lost.

JanStream proves that mission-critical digital public goods for India can be built with 
unbreakable resilience on AWS. 

Thank you to WeMakeDevs and Amazon Web Services!"
